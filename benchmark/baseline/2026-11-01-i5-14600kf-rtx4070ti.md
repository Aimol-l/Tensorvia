## 已知问题（基线即真相，Task 9 校准下限时逐条面对）

1. **全归约在三个设备后端慢几个数量级**：`sum f32 16M` CUDA 521ms /
   Vulkan 561ms（CPU 2.7ms）。根因：公共同款 API 把全归约展开成 axis=0 且
   outer=inner=1 的轴归约，轴内核的 total=1，只剩一个线程串行走完整个轴
   （旧 bench 只测提交、看不到设备耗时，三段计时才暴露出来）。SYCL 的
   OpenCL CPU 设备上是 8.9ms。修复归 Task 9。
2. **CPU 后端 `nll_loss` / `mse_loss` / `where` 等小用例的运行间方差 > 10%**：
   桌面机未钉核心，亚毫秒用例受调度影响（`nll_loss` 两次运行 0.077 vs 0.032ms）。
   >= 1ms 的用例方差在 10% 内。Task 9 定下限时要按这条给裕量。
3. **设备 lane 的 submit 与 sync 分离清晰**：CUDA 的 `add f32 16M` submit
   0.002ms / sync 0.325ms——异步提交的形态如预期；Vulkan 的 submit 偏大
   （命令录制 + fence 创建在调用线程上），where 一类算子 submit 37ms，值得
   Task 7/9 回头看。
