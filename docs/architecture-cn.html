Tensorvia 架构设计

跨平台多后端张量加速库 — 四层架构，Bridge 模式、自注册工厂、编译期模板特化分发的统一设计。

用户 API 层

Tensor 外观类 & ops:: 命名空间

用户入口。Tensor 提供静态工厂方法（Zeros、Ones、Random）、 运算符重载（+ - * /）、视图操作（.view()、.slice()、.t()、.permute()）、 设备迁移（.to_host()、.to_device()）。 所有算术、矩阵乘法、激活函数、归约等操作通过 ops:: 命名空间调用。

分发层

编译期后端选择 + 运行时类型解析

src/ops.cpp 通过 #ifdef BACKEND_XXX 在编译期选择唯一后端实现。 各后端内部，dispatch_dtype() 将运行时 DataType 枚举通过 std::type_identity<T> + lambda 转为编译期具体类型，为全部 8 种数据类型生成特化 kernel。

▼
抽象层

TensorImpl (Bridge) · ContextImpl · Metadata · 工厂

Tensor 持有 shared_ptr<TensorImpl>（多态设备存储）+ Metadata（栈上值类型：shape、strides、dtype、device、offset）。 视图操作零拷贝 — 共享同一个 TensorImpl，仅修改 Metadata。 自注册工厂将 Device 枚举映射到工厂函数，各后端在静态初始化期通过 Registrar 自动注册。

核心设计模式

Bridge 模式 — 存储抽象

Tensor 持有 shared_ptr<TensorImpl> + 栈上分配的 Metadata。
拷贝构造通过 TensorImpl::clone() 深拷贝。
视图操作（.slice()、.view()、.permute()）共享同一个 shared_ptr<TensorImpl> — 零拷贝，引用计数管理生命周期。
Metadata 是普通结构体，记录 shape、strides、dtype、device、offset。

自注册工厂

每个后端定义全局 struct XxxRegistrar，其构造函数调用 register_tensor_impl(Device::XXX, factory_fn)。
Registrar 是全局对象 — 构造函数在 main() 之前执行。
工厂是 Meyers' 单例：static unordered_map<Device, function>。
新增后端无需修改任何核心代码。

模板特化分发

每个算子声明为：
template<Device D> struct AddImpl; （主模板不完整）
各后端提供完整特化：
template<> struct AddImpl<Device::CUDA>
src/ops.cpp 通过 #ifdef BACKEND_XXX 选择 — 最终二进制只包含一个后端。
算子分发零虚函数调用开销。

std::type_identity 类型分派

dispatch_dtype(DataType, lambda) 将运行时枚举转为编译期类型：
case FLOAT32: f(std::type_identity<float>{});
lambda 接收 type_identity<T> 并推导 T，实例化类型特化 kernel。
compute_type_t<T> 将 float16/bfloat16 映射为 float，确保中间计算精度安全。

类继承层次

class TensorImpl { // 抽象接口
  virtual void* data() = 0;
  virtual unique_ptr<TensorImpl> clone() = 0;
  virtual void copy_to(shared_ptr<TensorImpl>) = 0;
  virtual shared_ptr<ContextImpl> context() = 0;
}

class CPUTensor —→ TensorImpl   (std::malloc / std::free)
class CUDATensor —→ TensorImpl   (cudaMalloc / cudaFree)
class SYCLTensor —→ TensorImpl   (sycl::malloc / sycl::free)
class VKTensor —→ TensorImpl   (vk::Buffer + vk::DeviceMemory)

class ContextImpl { // 抽象接口
  virtual void* ctx_raw_ptr() = 0;
}

class CUDAContext —→ ContextImpl   (持有 cudaStream_t)
class SYCLContext —→ ContextImpl   (持有 sycl::queue)
class VulkanContext —→ ContextImpl   (持有 vk::Device、Pipeline 缓存)

struct Metadata { // 普通值类型，栈上分配
  vector<int64_t> shape, strides;
  size_t numel; int64_t offset;
  Device device; DataType dtype;
}

class Tensor { // 用户接口（外观类）
  Metadata m_meta;
  shared_ptr<TensorImpl> m_impl;
}

工厂注册流程

1
静态初始化

全局 struct XxxRegistrar 对象的构造函数在 main() 之前执行。

2
注册工厂函数

构造函数调用 register_tensor_impl(Device::XXX, [](void* ptr, size_t numel, DataType dtype) { return make_shared<XxxTensor>(...); })

3
填充单例映射表

static unordered_map<Device, TensorImplFactory> 存储映射关系。Meyers' 单例避免静态初始化顺序问题。

4
运行时创建 Tensor

Tensor::Random({1024, 1024}, ...) 调用 create_tensor_impl(device, ptr, numel, dtype)，分派到对应工厂函数。

各后端内存管理

CPU

std::malloc 分配，自定义 FreeDeleter 用 std::free 释放。
无 ContextImpl — 直接操作主机内存。

CUDA

cudaMalloc 分配，cudaFree 释放。
CUDAContext 持有 cudaStream_t，自动选择显存最大的 GPU。

SYCL

sycl::malloc 分配，sycl::free 释放。
SYCLContext 持有 sycl::queue，支持 Intel/NVIDIA 多设备。

Vulkan

vk::Buffer + vk::DeviceMemory 管理。
VulkanContext 持有完整 Vulkan 设备栈：Instance、PhysicalDevice、Queue、CommandPool、Pipeline 缓存。
338 个 SPIR-V Compute Pipeline 在注册期预编译并缓存。

如何扩展

新增后端（如 Metal）

1. 在 Device 枚举中添加 METAL
2. 实现 MetalContext : ContextImpl
3. 实现 MetalTensor : TensorImpl
4. 为各算子添加 XxxImpl<Device::METAL> 特化
5. 在 src/init.cpp 中添加 MetalRegistrar
6. 在 CMakeLists.txt 中添加编译选项
核心层零修改。

新增算子（如 Floor）

1. 在 OpType 枚举中添加 Floor
2. 在 include/core/ops.h 中声明 API
3. 在各后端 ops/*.h 中声明模板特化
4. 在各后端 .cpp / .cu 中实现 kernel
5. 在 src/ops.cpp 中添加 #ifdef 分发
6. Vulkan 后端需额外编写 SPIR-V Compute Shader
