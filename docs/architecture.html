两条构建路径

mcppimport tensorvia;

模块门面 src/interface/tensorvia.ixx 由 tools/gen_facade.py 从 facade_exports.def 生成，全局模块片段里 #include 头文件事实源，只做导出。

后端按 --features cpu|cuda|sycl|vulkan 打开；.cu、.sycl、 .comp 分别由 rules-cuda、rules-sycl、rules-spirv 路由，SPIR-V 在构建期嵌入注册表。

测试：mcpp test --features … --accel …，tests/ 下一个文件一个二进制； benchmark/bench.cpp 同路径被发现，输出 submit / sync / total 三段与冷启动。

CMake#include <tensorvia.hpp>

直接构建头文件形态：模块扫描关闭，消费方只需普通的 include 与链接， 不要求工具链支持模块。入口是 python3 build.py -b cpu|vulkan|cuda|sycl， 编译与打包共用同一份后端参数。

Vulkan 的着色器由 build.py 在 configure 前用 glslangValidator 编译并生成 spv_registry.cpp（-gen-spv 可单独生成，打包路径 同样调用它）；CMake 只消费这份产物，configure 时缺失即报错——因此 vulkan 后端 必须经 build.py 构建。后端也可由 -DBACKEND_CUDA=ON 等开关 直接选择。

两条路径跑的是同一份头文件、同一个 SYCL 接缝与同一套着色器。

贯穿全库的约束

  • dispatch派发在编译期决定。没编入的后端不参与链接、不探测硬件、不加载驱动；请求它创建张量会直接报错。
  • errors不支持就是报错。未实现的算子与组合在调用点抛 runtime_error，错误信息点明后端，绝不静默回退 CPU。
  • async同步只发生在显式点。提交阶段零等待由计数器断言，不靠计时。
  • threads张量线程亲和。张量归创建它的线程所有；跨线程移交前必须先在原线程 ops::synchronize()，库不检测这种误用。
  • memory按流分池。缓存块只在释放它的流上复用；没有 record_stream，也没有公开的 Stream / Event 抽象。
