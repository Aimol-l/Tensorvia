Tensorvia Architecture

Cross-platform multi-backend tensor acceleration library — four-layer architecture with Bridge, Self-Registration Factory, and compile-time template specialization dispatch.

User API Layer

Tensor facade & ops:: namespace

User-facing entry point. Tensor provides static factories (Zeros, Ones, Random), operator overloads (+ - * /), view methods (.view(), .slice(), .t(), .permute()), and device transfer (.to_host(), .to_device()). All ops:: functions (arithmetic, matmul, activations, reductions, etc.) live here.

▼
Dispatch Layer

Compile-time backend selection + runtime type resolution

src/ops.cpp uses #ifdef BACKEND_XXX to select exactly one backend at compile time. Inside each backend, dispatch_dtype() converts the runtime DataType enum to compile-time type via std::type_identity<T> + lambda, generating fully specialized kernel code for all 8 data types.

▼
Abstraction Layer

TensorImpl (Bridge) · ContextImpl · Metadata · Factory

Tensor holds shared_ptr<TensorImpl> (polymorphic storage) + Metadata (stack value type: shape, strides, dtype, device, offset). View operations are zero-copy — they share the same TensorImpl with modified metadata. The self-registration factory maps Device → factory function, populated at static init by each backend's Registrar.

▼
Backend Layer

Per-backend specialized implementations

Each backend provides: a TensorImpl subclass, a ContextImpl subclass (except CPU), and template-specialized operation structs.

Design Patterns

Bridge Pattern — Storage Abstraction

Tensor holds shared_ptr<TensorImpl> + stack-allocated Metadata.
Copy constructor deep-copies via TensorImpl::clone().
View operations (.slice(), .view(), .permute()) share the same shared_ptr<TensorImpl> — zero-copy, reference-counted lifetime.
Metadata tracks shape, strides, dtype, device, and offset as a plain struct.

Self-Registration Factory

Each backend defines a global struct XxxRegistrar whose constructor calls register_tensor_impl(Device::XXX, factory_fn).
Registrars are global objects — their constructors run before main().
The factory is a Meyers' singleton: static unordered_map<Device, function>.
Adding a new backend requires zero changes to core code.

Template Specialization Dispatch

Each operation is declared as:
template<Device D> struct AddImpl; (incomplete primary template)
Each backend provides a full specialization:
template<> struct AddImpl<Device::CUDA>
src/ops.cpp uses #ifdef BACKEND_XXX — only one backend is compiled into the binary.
Zero virtual-call overhead for operation dispatch.

Type Dispatch via std::type_identity

dispatch_dtype(DataType, lambda) converts the runtime enum to compile-time type:
case FLOAT32: f(std::type_identity<float>{});
The lambda receives type_identity<T> and deduces T to instantiate type-specific kernels.
compute_type_t<T> maps float16/bfloat16 → float for safe intermediate arithmetic.

Class Hierarchy

class TensorImpl { // abstract interface
  virtual void* data() = 0;
  virtual unique_ptr<TensorImpl> clone() = 0;
  virtual void copy_to(shared_ptr<TensorImpl>) = 0;
  virtual shared_ptr<ContextImpl> context() = 0;
}

class CPUTensor —→ TensorImpl   (std::malloc / std::free)
class CUDATensor —→ TensorImpl   (cudaMalloc / cudaFree)
class SYCLTensor —→ TensorImpl   (sycl::malloc / sycl::free)
class VKTensor —→ TensorImpl   (vk::Buffer + vk::DeviceMemory)

class ContextImpl { // abstract interface
  virtual void* ctx_raw_ptr() = 0;
}

class CUDAContext —→ ContextImpl   (holds cudaStream_t)
class SYCLContext —→ ContextImpl   (holds sycl::queue)
class VulkanContext —→ ContextImpl   (holds vk::Device, pipeline cache)

struct Metadata { // plain value type, stack-allocated
  vector<int64_t> shape, strides;
  size_t numel; int64_t offset;
  Device device; DataType dtype;
}

class Tensor { // user-facing facade
  Metadata m_meta;
  shared_ptr<TensorImpl> m_impl;
}

Factory Registration Flow

1
Static Initialization

Global struct XxxRegistrar objects have constructors that run before main().

2
Register Factory Function

Constructor calls register_tensor_impl(Device::XXX, [](void* ptr, size_t numel, DataType dtype) { return make_shared<XxxTensor>(...); })

3
Singleton Map Populated

static unordered_map<Device, TensorImplFactory> stores the mapping. Meyers' singleton avoids static init order issues.

4
Runtime Tensor Creation

Tensor::Random({1024, 1024}, ...) calls create_tensor_impl(device, ptr, numel, dtype) which dispatches to the correct factory.
