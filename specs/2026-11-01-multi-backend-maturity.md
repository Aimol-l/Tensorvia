# Specification: Tensorvia 多后端成熟度——覆盖、性能下限与生态接入

## Metadata
- **Version**: 1.0.3
- **Status**: Draft
- **Author**: Claude Code
- **Created**: 2026-11-01
- **Last Updated**: 2026-11-01

## Overview

**现状**：Tensorvia 已具备 C++23 模块接口、四个后端（CPU / CUDA / Vulkan / SYCL）、约 60 余个算子名、373 份按 dtype 展开的 GLSL、编译期后端派发与"未实现即显式报错"的契约，四条本地 lane 可各自跑通。但"多后端张量库"目前仍是一个无法被检验的说法：

- 覆盖是隐式的——只有读源码或跑测试才知道某个算子在哪几个后端上存在；README 里那 5 个 CPU-only 例外就是例子。
- 性能没有任何可信数字——现有示例的耗时混入了逐层 `to_host()`、`.item()` 的同步往返与中转拷贝，无法区分内核、传输、同步各占多少；`benchmark/` 只有单机吞吐，没有同类基线。
- 300 余份按 dtype 复制的着色器让每个新算子的成本固定为 8 份左右，广度扩张带来的维护债在累积。
- 生态接入缺失：没有 DLPack 零拷贝互操作、没有包管理 recipe、示例全是随机权重，外部使用者无从接入也无从信任。
- CI 只覆盖 CMake 的 CPU lane，设备后端没有任何持续验证。

**目标**：把"多后端支持、性能过得去"从愿景变成可检验的属性。具体是四件事：(1) 覆盖矩阵成为一等公民，任何"看起来支持其实没有"都在 CI 里暴露；(2) 定义并测量性能下限——不追求峰值，但要能说清每个算子类别距可达到的上限有多远；(3) 补齐真实推理模型绕不过去的算子；(4) 打通互操作与分发，让库能被外部消费。本文是契约级 spec，不规定具体内核写法；实现顺序与切片由后续 plan 决定。

**非目标**：不追求峰值性能，不以 cuBLAS / cuDNN / oneDNN 为对标目标（Vulkan 作为参照见 FR-4）；不做 Autograd、训练、`nn.Module`、optimizer；不做量化（INT8/FP8 推理内核）、稀疏、complex dtype；不做 ONNX / safetensors 权重加载（互操作只到 DLPack 这一层）；不做计算图录制（已单独决策）。**不提供 C ABI，也不提供任何面向其他语言的绑定**：消费方式只有 C++（头文件与 C++23 模块），二进制 ABI 不承诺跨版本稳定。

**范围与阶段**：

| 阶段 | 主题 | 对应 FR |
|------|------|---------|
| P0 | 覆盖一致性：矩阵、例外清除、同步语义可见 | FR-1 / FR-2 / FR-5 |
| P1 | 性能下限：连续快路径、度量设施、逐类算子达标 | FR-4 |
| P2 | 推理最小算子集，真实权重跑通两个模型 | FR-3 |
| P3 | 生态接入：DLPack、包管理与消费示例 | FR-6 / FR-7 |
| P4 | 维护成本与持续验证：着色器收敛、骨架复用、CI 设备 lane | FR-8 / FR-9 |

P1 的度量设施（FR-4.1）优先于任何优化，否则"过得去"无法判定。

## Requirements

### Functional Requirements

- **FR-1 覆盖矩阵与承诺**：存在一份机器可读的“算子 × 后端”清单，每个组合标注为原生实现 / 组合实现 / 不支持，并与文档、README 同步。CI 检查清单与代码实际能力的一致性，任何漂移即失败。对外承诺：清单中标为原生或组合实现的组合，测试必须在对应 lane 上真实执行而非跳过。
- **FR-2 消除 CPU-only 例外**：`Prod`、`Erf`、`Sort`、`Topk`、`MaskedSelect`、`MaskedFill` 在设备后端上要么补齐原生实现，要么进入 FR-1 矩阵的“不支持”并由库显式拒绝。不得存在“文档没写、但设备上悄悄拒绝”的组合。可选的回退到 CPU 必须显式开启并附性能警告，默认关闭。
- **FR-3 推理最小算子集**：补齐任何 CNN / Transformer 推理都绕不过的算子：二维最大池化与平均池化、推理模式批归一化、`Gelu` / `LeakyRelu` / `Elu`、`Embedding` 视图语义；确认 `Chunk`、`Squeeze`、`Unsqueeze` 的可用性。验收以一个加载真实权重的 MNIST 级 CNN 与一个 tiny Transformer 为准，且网络定义中不得用 `reshape`/`permute` 手工拼装池化。
- **FR-4 性能下限契约**：
  - FR-4.1 **度量先于优化**：benchmark 套件把单次调用的耗时拆为内核、设备间传输、同步等待三部分，区分冷启动（含 JIT / 流水线创建）与稳态，并输出与同机基线的比值。没有该拆分，任何“性能”结论不成立。
  - FR-4.2 **连续快路径**：所有后端对连续输入走一维专用内核，非连续输入才进入通用 strided 迭代层。该分派对所有算子一致，并由测试覆盖“同一算子、连续/非连续输入结果一致”。
  - FR-4.3 **分类下限**：访存受限类（逐元素、激活、类型转换、转置、gather）以同机 memcpy 带宽为上限参照；归约类以同类的百分比为下限；矩阵乘与卷积以同机可获得的最佳实现为参照，`Vulkan` 的参照为 PyTorch CUDA 同尺寸结果（该后端无厂商库可对标）。**已于 2026-11-01 在 i5-14600KF + RTX 4070 Ti SUPER 上完成校准**（数据、复现方式与不达标项见 `docs/performance.md`，基线原始值见 `benchmark/baseline/`；CPU 的上限参照用与内核同并行度的并行 memcpy，单线程 clone 只作备查）。校准值（占参照的百分比，CPU / CUDA / SYCL / VULKAN）：访存受限——逐元素/激活 70/70/100/100，类型转换 40/50/70/100，转置 50/15/8/8，gather 20/15/10/1；归约——轴归约 100/10/100/25，全归约 30/1/15/1；计算——matmul 1024（Eigen / cuBLAS / PyTorch-CUDA 参照）60/8/8/5，conv2d（PyTorch 同尺寸参照）1/2/1/3。校准时有三项不达标（CUDA / VULKAN 全归约、VULKAN 类型转换），根因与归属单列于 `docs/performance.md`；这些项在修复前以下限为准记录现状，不算隐瞒。conv2d 全后端贴近下限（参照的 2~4%），余量 < 30%，同样记录在该文档。
  - FR-4.4 **同步只发生在显式点**：除 `to_host()` / `item<T>()` / `synchronize()` 与跨设备拷贝外，算子调用不得隐式等待设备。该性质由测试断言（例如连续提交若干算子后检查无同步计数增长）。
- **FR-5 同步语义可见化**：公开文档列明全部隐式同步点、异步句柄的生命周期规则、Vulkan 缓冲退役与 CUDA 流/分配器的交互。四后端遵循同一套表述。
- **FR-6 互操作**：提供 DLPack 导出与导入，要求零拷贝（导出时不复制存储，导入时按胶囊声明的 strides/dtype/device 建立视图）；不支持的设备或 dtype 必须显式拒绝而非静默复制。与 PyTorch 的双向往返需有测试。
- **FR-7 分发与消费**：纯 C++ 消费路径要顺畅——提供 CMake `find_package` 的完整使用示例、vcpkg 与 Conan 的 recipe 至少各一份，并同时验证“头文件 + 链接”与“`import tensorvia;`”两种接入方式。仓库内至少有一个从文件加载真实权重、输出可解释结果的示例。不提供 C ABI 或语言绑定。
- **FR-8 着色器与后端骨架收敛**：新增一个算子所需的着色器份数从“按 dtype 复制”降为“一份模板 + 构建期或运行期展开”；四后端的“校验 → 物化 → 启动”样板收敛为公共骨架，新算子只写内核与声明。该 FR 的度量指标是“新增一个算子改动的文件数”。
- **FR-9 诊断一致性与持续验证**：四后端对同类错误（越界、dtype 不符、设备不符、设备内存不足、设备丢失、索引超 32 位）给出同类信息与同一错误类别；CI 至少增加一条非 CPU 的 lane（软件 Vulkan 实现或 OpenCL CPU 上的 SYCL），使设备路径在托管环境中有基本覆盖。

### Non-functional Requirements

- **NFR-1 可检验性**：每个 FR 都有对应的自动化判定（测试、脚本或 CI 检查），不依赖人工阅读。无法自动化的项必须写明人工步骤。
- **NFR-2 可复现性**：性能与正确性结论必须记录硬件、驱动、编译器版本与构建 profile；benchmark 结果以“同机比值”为主，绝对数值为辅。
- **NFR-3 维护预算**：新增算子的边际成本不超过“每后端一份内核 + 一份着色器模板 + 一条矩阵条目 + 一组测试”；超出即视为 FR-8 未达成的回归。
- **NFR-4 兼容性**：保持“头文件 + C++23 模块”两种消费方式同步可用；兼容性承诺停在源码级（同一大版本内 API 不破坏），不承诺二进制 ABI 跨版本稳定，README 与包管理元数据需写明这一点。
- **NFR-5 文档同步**：覆盖矩阵、同步语义、性能表三份文档由构建脚本生成或校验，不手工维护副本。

## Test Steps

**覆盖一致性（FR-1 / FR-2）**

1. 运行矩阵生成脚本，与仓库内清单比对，期望无差异。
2. 人为在源码中删除某后端的算子实现，重新生成，期望 CI 检查失败并指出具体组合。
3. 四条 lane 分别运行全量测试，统计每个 lane 的跳过数；期望矩阵中标注支持的组合跳过数为 0。
4. 对 FR-2 的每个算子，在设备张量上调用：补齐的返回正确结果；未补齐的抛出带算子名的错误。

**性能下限（FR-4）**

5. 运行 benchmark 套件，确认输出中内核 / 传输 / 同步三段耗时之和与总耗时吻合，且冷启动与稳态分开统计。
6. 对每个访存受限算子，同一输入分别以连续与非连续视图调用，数值一致；连续路径的耗时不高于非连续路径。
7. 用同机 memcpy 作为带宽上限，逐个算子输出占比；对矩阵乘与卷积输出与参照实现的比值。
8. 在空闲设备上连续提交若干算子后立即取回结果，确认提交阶段没有同步等待；随后 `synchronize()`，确认结果正确。
9. 边界输入：空张量、0-dim、单元素、半精度、跨步视图、带 offset 的视图、超过 32 位的元素数（Vulkan 应显式拒绝）。

**推理算子（FR-3）**

10. 用加载的真实权重跑 CNN 示例与 tiny Transformer 示例，与 PyTorch 参考输出的最大绝对误差在 float32 容差内；网络定义中不出现手工池化。
11. 在四条 lane 上各跑一次两个示例，比较输出一致性。

**互操作与分发（FR-6 / FR-7）**

12. DLPack 导出到 PyTorch、PyTorch 导出回 Tensorvia，分别修改一侧数据后确认另一侧可见（零拷贝判据），并检查 strides / dtype / 设备一致。
13. 在干净容器中按 README 的 CMake 示例构建并运行 hello-world；按 vcpkg / Conan recipe 各构建一次。
14. 分别用“头文件 + 链接”与“`import tensorvia;`”写两个最小消费程序，在干净环境中构建运行，两者对同一段逻辑给出相同结果；错误路径抛出带算子名的异常（C++ 异常，不引入错误码体系）。

**维护与持续验证（FR-8 / FR-9）**

15. 记录一次“新增一个算子”的实际改动文件数，与 NFR-3 的预算比对。
16. 人为触发设备越界索引、dtype 不符、设备内存不足，比较四后端的错误类别与信息结构。
17. 在 CI 的非 CPU lane 上跑通全量测试的至少一个子集，并确认该 lane 的命令与本地 lane 文档一致。

**边界与异常（贯穿）**

18. 设备丢失或 fence 超时：确认错误可捕获、资源可回收、后续调用不挂起。
19. 多线程：两个线程各自提交到不同设备通道，确认结果正确且无数据竞争（sanitizer 下运行）。
20. 同一进程内多次 `synchronize()` 与析构顺序：确认无泄漏、无对已释放缓冲的引用。

## Acceptance Criteria

- **AC-1** 覆盖矩阵存在、可生成、被 CI 校验；矩阵与 README、文档三者一致。
- **AC-2** 四条 lane 上，矩阵标注为支持的组合零跳过；FR-2 的六个算子不再出现“文档未提但设备拒绝”的情况。
- **AC-3** benchmark 套件能拆分内核 / 传输 / 同步耗时，并在仓库中保存一份带硬件信息的基线表。
- **AC-4** 连续快路径在全部后端生效；连续与非连续输入结果一致，且连续路径更快。
- **AC-5** 访存受限算子达到校准后的带宽占比下限；矩阵乘与卷积达到校准后的参照比值。具体数值在基线测量后补记于本 spec，允许分后端不同。
- **AC-6** 除显式点外无隐式同步，并由测试断言。
- **AC-7** 两个真实权重的模型在四条 lane 上跑通，输出与 PyTorch 参考在容差内一致。
- **AC-8** DLPack 双向零拷贝往返通过测试；CMake / vcpkg / Conan 三条消费路径在干净环境中可用，且头文件与 `import tensorvia;` 两种接入方式都能构建运行。
- **AC-9** 新增一个算子的改动文件数落入 NFR-3 预算；着色器按 dtype 复制的份数显著下降。
- **AC-10** CI 中存在非 CPU lane 并稳定运行；同步语义文档列出的隐式同步点与代码一致。
